This is a simple test to measure battery performance on Linux. The test opens and scrolls through browser tabs (Chrome or Firefox) while `powerstat` records the drain, and saves the measurement into the `powerstat` folder automatically.

While this code was generated by AI and is quite simple, the best measure for battery life remains real-world testing during your daily use.

## Results: Firefox vs Chrome

Measured 2026-09-19 with **TLP in energy saving mode**, on battery, machine
otherwise idle. Firefox 152.0.1 against Google Chrome 149.0.7827.155, same
workload, back to back, 300 samples each.

| Browser | Avg W | StdDev | Min W | Max W | Run |
| --- | --- | --- | --- | --- | --- |
| Firefox 152 | **9.38** | 2.90 | 4.80 | 15.47 | `firefox_clean_20260919-104822.txt` |
| Chrome 149 | **11.27** | 3.96 | 6.59 | 30.46 | `chrome_clean_20260919-105640.txt` |

**Firefox drew 1.89 W less, roughly 17% lower.** The gap is in the peaks rather
than the floor: Chrome topped out at 30.46 W against Firefox's 15.47 W, on
minimums only 1.8 W apart.

Firefox was measured twice that day, half an hour apart, at 9.41 W and 9.38 W,
so the method reproduces to within 0.03 W. Chrome has only one valid run behind
its number, so treat the gap's size as approximate even though its direction is
clear.

## Setup

```sh
python -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Browser drivers are handled by Selenium Manager, so there is nothing to install by hand beyond the browser itself.

## Running a measurement

```sh
.venv/bin/python main.py --browser firefox --label optimized_hybrid
```

`--label` names the hardware/power configuration under test. The result lands in
`powerstat/<browser>_<label>_<timestamp>.txt`, so a rerun never overwrites an
earlier measurement.

powerstat owns the clock. It starts first, the browser opens its tabs during the
180 second pre-measurement delay so sampling begins against a warm steady
state, and the tab-refresh/scroll workload loops until powerstat has taken all
300 samples. Then the browser closes and the average wattage is printed.

Measure on battery, not on AC — on AC the battery gauge has no drain to report.

| Flag | Default | Meaning |
| --- | --- | --- |
| `--browser` | `chrome` | `chrome` or `firefox` |
| `--label` | required | name of the configuration being measured |
| `--delay` | `180` | seconds powerstat waits before sampling (the warm-up) |
| `--interval` | `1.0` | seconds between samples |
| `--samples` | `300` | number of samples |
| `--rapl` | off | measure the Intel RAPL counters instead of the battery gauge (needs root) |

powerstat refuses runs shorter than **480 seconds** total (`delay + interval ×
samples`), which is why the defaults add up to exactly that. With `--rapl` the
floor drops to 60 seconds, but reading the RAPL counters requires root.

## Comparing measurements

```sh
.venv/bin/python main.py --summary
```

Parses every file in `powerstat/` and prints them lowest average power first:

```
Run                                            Avg W   StdDev    Min W    Max W  Samples
----------------------------------------------------------------------------------------
optimized_integrated                           10.65     2.53     7.00    18.73      300
not_optimized_integrated                       10.85     2.66     6.96    21.40      300
not_optimized_hybrid                           11.86     4.71     6.86    33.79      300
```

A run that was cut short is listed as skipped rather than silently averaged in.
powerstat prints a full summary even when it is killed, so completeness is judged
by comparing the readings a file actually contains against the sample count it
declares — averaging four readings out of 300 looks like a result while meaning
nothing. Such a run also exits non-zero and says how far it got.

A single tab that hangs or errors is logged and skipped so it cannot throw away
an eight-minute measurement; only a browser that fails on every tab in a cycle
aborts the run.

## Tests

```sh
.venv/bin/python -m pytest
```

Covers the run-length validation, the output-path naming, and the powerstat
output parsing — including a check that every measurement committed to
`powerstat/` still parses.
